# AI小学学习系统 V2.3 · 自适应学习引擎（Adaptive Learning Engine）

> 版本口径说明：本项目代码里 V2.3 包含两批能力 ——
> **①知识掌握模型 + 错因分析 + 题目审核**（见 `V2.3知识掌握与错因分析说明.md`），
> **②自适应学习引擎**（本文）。需求文档把 ① 记作 V2.2，本文按需求口径把 ② 记作 V2.3。
>
> V2.2 能回答"哪里薄弱、为什么错"，V2.3 回答"**下一步到底学什么、出多难的题、什么时候升降难度**"。

全部本地运行、SQLite 存储、FastAPI 架构，数据一律绑定 `student_id`。

---

## 一、闭环

```text
学生
 ↓  能力模型（AbilityProfile 能力阶段 + MasteryEngine 掌握度 + 错因分析）
 ↓  学习策略（LearningStrategy：学什么知识点、为什么）
 ↓  难度决策（DifficultyController：出多难、什么时候升降）
 ↓  任务生成（DailyLearningPlanner 今日计划 + QuestionSelector 下一题）
 ↓  答题（/api/learning/next-question → /submit）
 ↓  更新能力（掌握度 / 能力分 / 错题本 / 复习计划）
 ↓  下一轮调整（/api/learning/feedback 主观感受 + 重新 recommend）
```

闭环由 `backend/adaptive/engine.py` 的 `AdaptiveLearningEngine` 串起来：
它只负责**从数据库组装画像**和**把决策落库**；算法全部在四个纯函数模块里。

## 四、算法说明

### 1. 知识点选择（`strategy.py`）

优先级（**不是简单取最低分**）：

| 优先级 | 规则 | 档位加成 |
| --- | --- | --- |
| 1 | 高价值薄弱知识点：`mastery_score < 70` | +0.30 |
| 2 | 影响后续知识的基础知识：被依赖度 ≥ 0.34 且未到 85 分 | +0.18 |
| 3 | 近期错误频繁：错误压力 ≥ 0.34 | +0.10 |
| 4 | 即将遗忘：复习到期 / 超过 10 天没练 | +0.04 |
| 5 | 其它（含"从没练过"） | 0 |

综合得分：

```text
score = 档位加成
      + 0.35 × 薄弱度      (100 − 掌握度) / 100
      + 0.25 × 基础权重     被依赖知识点数 / 3（上限 1.0）
      + 0.20 × 错误压力     0.6 × 历史错误率 + 0.4 × 最近错因次数/3（连续错 2 次 +0.2）
      + 0.20 × 遗忘风险     到期直接 1.0，否则 min(1, 距上次练习天数 / 10)
      + 0.12 × 阶段命中     （仅"没练过"的知识点，命中当前能力阶段才加）
      − 0.25 × 已熟练       （掌握度 ≥ 85 不再反复练）
      + 0.55 × 依赖门控     （它是别人卡住的基础）
```

**依赖门控（关键设计）**：应用题掌握 60、乘法掌握 50，而应用题依赖乘法时，先把乘法顶上来。

```text
表内乘法 50 ──→ 两步计算应用题 60      →  推荐「表内乘法」（它是基础）
表内乘法 78 ──→ 两步计算应用题 60      →  推荐「两步计算应用题」
表内乘法 没练过 ──→ 两步计算应用题 60  →  推荐「两步计算应用题」（不误判拦路虎）
```

门控只在"前置**练过**、掌握度低于 70、且比当前知识点更薄弱"时生效 ——
没练过不等于没学会，不能凭空白记录抢走练习机会。

依赖关系表覆盖三科共 69 条边（`strategy.DEPENDENCIES`，每科 23 条），并提供：

```python
strategy.prerequisites("数学", "两步计算应用题")   # ['表内乘法', '100以内加减法']
strategy.dependents("数学", "表内乘法")            # 依赖它的 7 个知识点
strategy.foundation_weight("数学", "表内乘法")     # 1.0（被 3 个以上依赖）
strategy.dependency_chain("数学", "两步计算应用题") # ['两步计算应用题', '表内乘法', '20以内加减法']
```

输出的 `next_action`：

```json
{"action": "practice", "subject": "数学", "knowledge": "两步计算应用题",
 "difficulty": 72, "reason": "掌握度62，需要强化", "priority_score": 0.68,
 "tier": 1, "dependency_chain": ["两步计算应用题", "表内乘法", "20以内加减法"]}
```

### 2. 难度动态调整（`difficulty.py`）

目标：把孩子稳定在**最佳学习区间**（正确率 70%~85%）。

| 观察 | 调整 |
| --- | --- |
| 连续答对 5 题 | 难度 +5（每满 5 题再升一档，单次最多 +10） |
| 连续答错 3 题 | 难度 −10（每满 3 题再降一档，单次最多 −10） |
| 最近 10 题正确率 ≥ 90% | `stage_action = "up"` 提升阶段 |
| 最近 10 题正确率 < 50% | `stage_action = "down"` 降低阶段 |
| 反馈"简单 / 有点难 / 不会" | 难度 +3 / −3 / −6 |

约束：

- 难度恒在 **1~100**，单次幅度不超过 ±10。
- **连对/连错与正确率窗口不重复计分**：连续答对 5 题就只 +5（不是 +10），
  正确率窗口这时只负责"提升阶段"；只有没有连对/连错时，窗口才顺手推一点难度。
- 窗口样本不足 5 题时只看连对/连错，避免"错一道就降难度"。
- 难度基准 `base = 0.5 × 能力分 + 0.5 × 知识点难度`（与既有出题逻辑一致），再叠加以上调整。

返回结构：

```json
{"difficulty": 55, "base": 50, "delta": 5, "streak": {"kind": "correct", "count": 5},
 "window_rate": 1.0, "window_size": 5, "on_target": false, "stage_action": "up",
 "target_range": [70, 85], "reason": "连续答对 5 题，难度 +5；最近 5 题正确率 100%，进入提升阶段"}
```

### 3. 下一题推荐（`selector.py`）

四项证据加权：

| 权重 | 证据 | 计算 |
| --- | --- | --- |
| 40% | 知识薄弱度 | `(100 − 掌握度) / 100` |
| 30% | 当前能力匹配 | `1 − |知识点难度 − 目标难度| / 100` |
| 20% | 遗忘风险 | 同上（到期 / 久未练） |
| 10% | 随机探索 | 随机数，避免路径完全固定 |

另外两条防呆规则：

- **题源配比 70 / 20 / 10**：70% 当前薄弱知识、20% 复习旧知识、10% 挑战知识。
- **同知识点回避**：最近 3 题练过的知识点 −0.35，避免"一直做同一种题"。

### 4. 每日计划（`planner.py`）

默认 35 分钟：数学 15 / 语文 10 / 英语 10。

| 科目 | 每题耗时 | 15/10 分钟 → 题量 | 目标文案示例 |
| --- | --- | --- | --- |
| 数学 | 90 秒 | 10 题 | 应用题强化，完成 10 题 |
| 语文 | 60 秒 | 10 题 | 读一篇短文，完成 10 题 |
| 英语 | 30 秒 | 20 个 | 复习 20 个单词 |

规则：

1. 先按科目固定分配，再按总时长等比缩放（下限 5 分钟、上限 30 分钟）。
2. **已经熟练（平均 ≥85）的科目让出 5 分钟**，补给最薄弱的科目。
3. 目标掌握度 = 当前掌握度 + 10（上限 90，未练习按 70）。
4. 同一学生同一天**幂等**：已生成的计划复用，完成进度不会因为刷新页面丢；
   不在新计划里的空计划标记 `expired`。

### 5. AI 出题升级（`deepseek.ability_block`）

prompt 里不再只有年级，而是整段学生画像：

```text
学生：小朋友A（三年级）
当前能力：数学3.2阶段（三年级熟练）
目标阶段：3.3（三年级进阶）
知识点：两步计算应用题
掌握度：65，这次练习的目标是提升到 75 以上
错误历史：审题错误较多，出题时针对这个薄弱点设计
目标：按自适应难度 72/100 出题，略高于当前能力，让孩子努力一下能做对
出题要求：让孩子努力一下能做对，不要超出目标阶段太多。
```

难度由自适应引擎给出（`/question?difficulty=`，0 表示不指定、走原有规则），
题目仍然要过 `validator` 质量审核，不合格重试一次，再不合格用内置兜底题。

## 五、API 说明

统一前缀 `/api/learning`，错误码：`400` 科目/感受非法，`404` 题目不存在。

### 1. `GET /api/learning/recommend/{student_id}?subject=数学`

今日推荐学习内容（`subject` 可省略 → 三科都给，并给出首要科目）。

```json
{
  "student_id": 1, "date": "2026-10-04",
  "student": {"id": 1, "name": "小朋友A", "grade": 1},
  "next_action": {"action": "practice", "action_text": "强化练习", "subject": "数学",
                  "knowledge": "两步计算应用题", "difficulty": 62,
                  "reason": "掌握度60，需要强化"},
  "primary": {"...": "完整的决策（含候选、证据、依赖链）"},
  "subjects": [{"subject": "数学", "ability": {}, "summary": {}, "decision": {}, "difficulty_state": {}}],
  "plan": {"date": "2026-10-04", "minutes": 35, "items": []},
  "strategy_log_id": 12,
  "message": "今天先练「两步计算应用题」：掌握度60，需要强化，今天还剩 8 题"
}
```

### 2. `POST /api/learning/start`

开始学习任务（锁定知识点与难度，把该科计划标成进行中）。

请求：`{"student_id": 1, "subject": "数学", "knowledge": "两步计算应用题", "plan_id": 0}`
（`knowledge` 省略则用自适应推荐的知识点）

响应：`{"knowledge", "difficulty", "mode", "reason", "target_count", "completed_count", "plan_id", "plan", "difficulty_state", "strategy_log_id"}`

### 3. `GET /api/learning/next-question?student_id=1&subject=数学&knowledge=&qtype=choice`

获取下一题：知识点与难度都由自适应引擎决定，出题走主流程（题库 + 质量审核 + 兜底）。

响应 = `/question` 的全部字段 + `adaptive`：

```json
{"question_id": 88, "qtype": "choice", "difficulty": 62, "question": "...", "options": {},
 "adaptive": {"action": "practice", "mode": "practice", "knowledge": "两步计算应用题",
              "difficulty": 62, "reason": "薄弱知识优先：两步计算应用题（掌握度 60）",
              "breakdown": {"weakness": 0.4, "match": 0.9, "forgetting": 0.2, "random": 0.5},
              "difficulty_state": {"difficulty": 62, "delta": 5, "stage_action": "up"},
              "decision": {"candidates": [], "dependency_chain": []}}}
```

### 4. `POST /api/learning/feedback`

提交学习反馈（对错 / 难度感受 / 是否需要帮助），并返回下一次难度建议。

请求：`{"student_id": 1, "subject": "数学", "knowledge": "两步计算应用题", "question_id": 88,
       "correct": false, "feel": "hard", "need_help": true, "note": "不会列式"}`

响应：

```json
{"saved": true, "feel_text": "有点难", "need_help": true,
 "next_difficulty": 52, "difficulty_delta": -10,
 "difficulty_reason": "连续答错 3 题，难度 -10",
 "stage_action": "hold", "on_target": false,
 "message": "没关系，觉得难说明正在进步：下一题难度会降一点，先把基础打牢。",
 "plan": {"id": 1, "completed_count": 3, "target_count": 10, "status": "doing"},
 "feel_options": [{"value": "easy", "text": "😊 简单"}, "…"]}
```

### 5. `GET /api/learning/plan/{student_id}?date=&refresh=`

查看今日计划（没有就按当前画像自动生成）。`refresh=true` 重新安排今天（未完成的作废重建）。

### 6. `GET /api/learning/strategy-log/{student_id}?limit=20`

策略日志 + 反馈历史 + 计划参数，用来回答"系统为什么这么安排"。

## 八、设计决策与限制

1. **难度状态不建表**：连对/连错、最近 10 题正确率都由 `answer_records` 现算，
   避免"状态表与实际记录不一致"这类经典 bug。
2. **主观感受只在 2 小时内生效**：`feel` 影响难度，但只认最近 2 小时的反馈，
   防止几天前的一次"有点难"反复拉低难度。
3. **依赖关系是显式表**，不是从阶段顺序自动推导：阶段顺序只影响出题难度，
   不代表学习先后（例如"长度单位与测量"阶段比"表内乘法"晚，但两者互不依赖）。
4. **未练习 ≠ 没学会**：依赖门控忽略没有练习记录的前置知识点。
5. **计划完成数按"作答次数"计**，答对答错都算完成（做完就是收获），
   但掌握度、能力分、错题本只按对错更新。
6. 已知限制：一天内多次刷新计划会复用已有计划（这是有意为之），
   知识点变化要用 `?refresh=true`。
