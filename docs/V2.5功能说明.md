> 答对自动跳下一题 / 答错出解析、不再额外做能力诊断（改由训练成绩自动判断）、

> 表头「小智学伴」→「菲比同学」（需求 9、10）。

## 2. 菲比三视图立牌（`frontend/phoebe3d.js`）

### 2.1 素材怎么来的

用户给的是一张**「6 情绪 × 3 视角」宫格图**（行 = 开心 / 难过 / 点赞 / 加油 / 可爱 / 鼓励，
列 = 正面 / 侧面 / 背面，1536×1024，公仔为实物毛绒玩偶照片）。
处理方式（离线一次性，由 `tools/crop_phoebe3d_sheet.py` 完成，不进入运行时）：

1. 32×32 分块迭代估出**逐像素 2D 背景场**（块内中位数初始化，取离当前估计最近的 30% 求均值，双线性上采样），
   解决浅色渐变背景的 L1 系统偏差（逐行单色模型会把白帽顶误判成背景）；
2. 「到背景距离 ≤ 26」+「局部梯度 ≤ 30」双判据得到可通行区域，从画布边缘泛洪，
   只把**与画布边缘连通**的背景域置为透明 —— 白帽顶/发丝虽然也接近背景色，但被轮廓梯度阻断，完整保留；
3. 行间白色分隔带与公仔脚下亮面是「比背景亮 + 极低梯度」的平滑亮区，会把同列 6 个公仔连成
   1024px 高的连通域，因此**额外开一条通道**（`grad ≤ 20 & dist ≤ 240 & bright ≥ 4 & dark ≤ 2`）让泛洪穿过去；
4. 几何抹除每格的「正面 / 侧面 / 背面」文字水印（18 个矩形已知，配合「饱和度 ≤ 34」判据，实测零误伤），
   再按连通域面积/厚度丢掉噪声碎片；
5. 按 bbox 质心把连通域归到 18 个格子（面积最大者为主组件，其余按最近距离并入）取并集 bbox 裁切，
   统一画布 `338×210`、**底部对齐**；
6. 产出 `{情绪}_{视角}.png` 共 18 张 + `manifest.json`（源图 `source.png` 一并保留便于重裁）。

> 三视图只有三个真实角度，第 4 个角度（270°）用**侧面的水平镜像**补足，
> 于是 0°/90°/180°/270° 构成完整一圈；6 种情绪各有这一圈。

素材预览（6 情绪 × 3 视角共 18 张，直接取自 `frontend/assets/phoebe3d/`；
本图由 `python tools/make_phoebe3d_doc_preview.py` 生成，重裁素材后跑一次即可刷新）：

![菲比 6 情绪 × 3 视角素材预览](images/phoebe3d_views.png)

> 立牌在页面上就是在 18 张里挑一套：旋转 = 相邻视角交叉淡化 + 松手后停靠到最近正视角（见 2.2），
> 换表情 = 三个视角的 `src` 一起换（见 2.5.1）。

### 2.2 旋转是怎么算的

纯函数（可直接单测）：

- `normalizeAngle(a)`：任意角度规整到 `[0, 360)`
- `angleDistance(a, b)`：最短夹角（0~180）
- `frameWeights(angle)`：每个视角的显示权重，`w = max(0, 1 - 夹角/90)` 后归一化（和为 1）
  - 正对某视角时该帧权重为 1；两个视角正中时各 0.5，即"交叉淡化"过渡
- `viewKeyForAngle(angle)`：`front` / `side` / `back` / `side-mirror`

DOM 层把 4 个 `<img>` 绝对定位叠放，逐帧写 `opacity`；拖动灵敏度 0.65°/px，松手有惯性（衰减 0.92），
空闲时在基准角度附近按 6.4s 周期 ±12° 缓慢摆动（"公仔是活的"）。

### 2.3 互动

| 操作 | 反应 |
|---|---|
| 按住左右拖动 | 旋转，松手带惯性 |
| 拖动距离 < 6px（点击） | 说一句随机台词（语音 + 字幕） |
| 键盘 ← / → | 每次转 15°（可访问性） |
| 鼠标悬停 | 光标变抓手 |

### 2.4 语音 + 字幕

- 字幕：公仔上方的气泡（`.p3d-caption`），默认停留 3.6s，HTML 已转义
- 语音：浏览器 `speechSynthesis`，优先挑中文音色，朗读前 `cancel()` 避免叠音
- 页面提供开关（今日学习页"🔊 菲比语音"），状态存 `localStorage["xiaozhi.phoebeVoice"]`
- 浏览器不支持语音、或系统没有中文音色时：**只显示字幕**，功能不中断

### 2.5 答题反馈（两页共用）

`phoebe3dFeedback(correct, options)`：

- **答对**：立牌跳跃欢呼 + **换成开心表情**（连对 ≥2 题换「点赞」）+ 弹表情包浮层（`phoebe.js` 的 `celebrateCorrect`，含欢呼人声）+ 打字幕
  —— 字幕与表情包同时出现，但**不额外播 TTS**（避免人声与音效打架）
- **答错**：立牌摇头 + **换成难过表情** + TTS 语音 + 字幕提示，并清零连对计数
- **`options.mood`** 可以显式指定表情（错题本「再练答对」传 `"cheer"` 换成加油）

模块缺失（比如某个页面没引入）时所有调用静默降级，绝不影响做题。

### 2.5.1 表情切换（6 情绪 × 3 视角）

`setMood(mood)` / 全局 `phoebe3dMood([mood])`，`mood ∈ happy | sad | like | cheer | cute | encourage`：

- 4 个旋转图层始终只有 4 个 `<img>`：切表情是**换 `src`**（`assets/phoebe3d/{情绪}_{视角}.png`），不是加图层；
- 换之前先把三个视角 `new Image()` **预载好**，全部 `onload` 才一次性换图；
  任何一张加载失败就**保留当前形象**（绝不白屏或半新半旧），自增 `moodToken` 保证只有最后一次请求生效；
- 触发映射：点击立牌 → `cute` + AI 台词；答对 → `happy`；连对 ≥2 题 → `like`；答错 → `sad`；
  错题本再练答对 → `cheer`；空闲 60s（`IDLE_MOOD_MS`）没操作 → `encourage`；待机默认 `like`。

### 2.6 挂载与位置

- **位置：浏览器左侧空白处**。页面里放 `<div data-phoebe3d></div>` 才会嵌进内容区；
  V2.5 起三个答题/能力页**都不再放宿主**，所以立牌一律走浮动模式：
  `position: fixed; left: 18px; top: 50%; transform: translateY(-50%)`（左侧垂直居中）。
- **鼠标滑动不改变位置**：立牌不监听鼠标移动做任何位移，拖拽只改旋转角度（`state.angle`），
  代码里从不写 `style.left/top/position`；`position: fixed` 也保证页面滚动时它不动。
- **窄屏适配**（左侧空白被压缩时）：
  | 视口宽度 | 表现 |
  |---|---|
  | ≥ 1280px | 200×237 立牌，`left: 18px` |
  | ≤ 1280px | 缩到 160×190，`left: 10px` |
  | ≤ 1060px | 缩到 128×152，隐藏拖动提示 |
  | ≤ 900px | 隐藏（卡片几乎占满宽度，没有"左侧空白"，隐藏比遮挡好） |

### 2.7 台词由 DeepSeek 生成（点击触发）

用户要求：**不用写死的台词**，每次点击都触发一次反馈，除了日常用语还要读学习数据、由 AI 分析后输出。

```
点击立牌 → 字幕先显示"让菲比看看你的学习情况…"
        → POST /api/phoebe/chat {student_id, trigger:"click"}
        → 后端聚合学习数据快照 → 交给 DeepSeek → 清洗成一句话
        → 字幕显示 + 语音朗读（字幕停留时长按字数估算，长句不会一闪而过）
```

**学习数据快照**（`phoebe_ai.learning_snapshot`，全部只读）：

| 字段 | 内容 | 来源 |
|---|---|---|
| `today` | 今天做了几题、对几题 | `answer_records`（按当天过滤） |
| `subjects` | 各科能力阶段 / 能力分 / 题量 / 正确率 | 复用 `auto_ability.profile_for` |
| `weak` | 最该补的 3 个知识点（掌握度最低） | `student_knowledge_mastery` |
| `strong` | 已经不错的知识点（≥80 分、≥3 题） | `student_knowledge_mastery` |
| `wrong` | 错题本 NEW / LEARNING / MASTERED 数量 | `wrong_questions` |
| `due_reviews` | 该复习的知识点 | `student_knowledge_mastery.next_review_time` |
| `recent` | 最近 5 次作答明细 | `answer_records` |

**发给模型的约束**（写在 prompt 里，`build_prompt`）：只输出一句话、15~45 字、
不要引号 / Markdown / emoji、要结合数据说具体的东西、**不许编造数据里没有的内容**、语气温暖不说教。

**三层降级**（保证任何情况下都有话说）：

| 情况 | `source` | 结果 |
|---|---|---|
| 正常 | `ai` | DeepSeek 生成的台词（实测 0.7~1.2s） |
| 没有 `DEEPSEEK_API_KEY` | `fallback_no_key` | 规则文案，仍然带学习数据（"今天练了 5 题啦，还有 1 个知识点该复习"） |
| 设了 `PHOEBE_AI_OFFLINE=1` | `fallback_offline` | 同上，完全不联网（验证脚本与不想联网的家长用） |
| 超时 / 网络异常 / 模型返回空 | `fallback_error` / `fallback_empty` | 同上 |

前端还有一层：后端整体不可达或 14 秒没回，立牌直接用本地台词兜底，**永远不会卡在"正在看学习情况…"**。

**答对 / 答错的反馈仍然是本地即时文案**（保证答题节奏与 1.7 秒自动跳题），
只有"点击"走 AI —— 想让孩子答完等 1 秒听 AI 说话，可以把 `phoebe3dFeedback`
里的 `correct` 分支改成调用 `viewer.askAi("correct")`。

## 3. 今日学习页 / 自由练习页的行为变化

### 3.1 答对自动跳下一题

```
作答 → 判分 → 答对
        ├─ 菲比：跳跃 + 表情包 + 字幕
        ├─ 自动提交一次学习反馈（推进今日计划完成数）
        └─ 1.7s 后自动 loadNext()
```

> 关键约束：今日计划的 `completed_count` **只在 `/api/learning/feedback` 里 +1**（`adaptive/engine._advance_plan`）。
> 所以"自动跳题"时必须补一次反馈，否则进度条永远不动。
> 反馈的 `feel` 字段留空（孩子没表态），并带 `note="auto"` 便于区分；
> `feedbackSent` 保证**每题只提交一次**，不会因为自动提交 + 手动点感受而重复计数。

### 3.2 答错出解析并停留

- 渲染"❌ 答错了，一起看看解析" + 正确答案 + 橙色的「📖 错题解析」框（完整 `analysis`）
- 菲比摇头 + 语音 + 字幕
- 给出难度感受按钮（😊🙂🤔😵 / 🆘 需要帮助）与「我明白了，下一题 ➡️」
  —— 点感受会提交带 `feel` 的反馈（自适应难度据此调整），直接点下一题则用空 `feel` 补交一次

### 3.3 自由练习页（`index.html` / `app.js`）

同样接入立牌 + 语音字幕；答对 1.7s 后自动换题，答错停在解析页。
原有 `celebrateAnswer(correct)` 守卫函数保留（兼容只加载 `phoebe.js` 的场景）。

## 4. 训练成绩自动能力诊断（`backend/auto_ability.py`）

### 4.1 为什么这样做

旧流程要求孩子先在 `diagnostic.html` 做一轮 24 阶段的专门诊断；
用户要求**去掉这一步**：水平应当从"每天练什么、答得怎么样"里自然看出来。

### 4.2 算法（纯函数 `subject_profile(records, subject)`）

样本：该科最近 **40 条** `answer_records`（今日学习页与自由练习页都写这张表）。

| 量 | 规则 |
|---|---|
| 能力分 `score` | 加权平均难度：答对权重 1.0、答错权重 0.35；`Σ(difficulty×w)/Σ(w)`，保留 1 位 |
| 能力阶段 `stage` | `stages.key_of_difficulty(score)` → `"3.2"`，再取 `label` / `stage_range` |
| 一致性 `consistency` | 答对题难度的标准差 s → `max(0, 1 - s/40)`；答对题 < 2 条记 0.5 |
| 题量因子 `volume` | `min(1, n/20)` |
| 置信度 `confidence` | `0.6×volume + 0.4×consistency`；`≥0.75` 高、`≥0.45` 中、否则低 |
| 状态 `status` | `n = 0` → `unknown`（还没数据）；`n < 5` → `warming`（积累中）；否则 `ready` |
| 依据 `reason` | 中文一句话：多少题、正确率、稳定答对的难度、推断出的阶段 |
| 建议 `next_step` | 分 unknown / warming / ready 三种口吻 |

`overall` = 有数据科目的 `score` 平均（三科都没数据时 `stage` 为空串）。

### 4.3 接口

```
GET /api/ability/auto/{student_id}     # 只读，不写任何表
```

返回 `student_id` / `source`（固定 `"training"`）/ `generated_at` / `total_answers` / `overall` / `subjects[3]`，
每科含 `status` `score` `stage` `stage_label` `range` `stars` `star_text` `confidence`
`confidence_text` `answer_count` `correct_count` `correct_rate` `knowledge_focus` `reason` `next_step`。

学生不存在或没有记录时**不返回 404**，而是三科 `status="unknown"` 的正常结构，前端可直接渲染。

### 4.4 前端

- 新页面 `frontend/ability.html` + `ability.js`：「我的能力水平」，
  顶部写清楚"不是考试考出来的"，每科展示星级、阶段、能力分、当前重点、题量/正确率/可信度、
  判断依据与下一步建议；无数据的科目给"先练几道题"。
- `today.html`、`index.html` 的导航入口从 `diagnostic.html` / `diagnostic_report.html` 换成 `ability.html`；
- 今日计划为空时的文案从"先做一次能力诊断"改为"先自由练几道题，系统会自动看出你的水平"。
- `diagnostic.html` / `diagnostic_test.html` / `diagnostic_report.html` **保留不动**（仍可直接访问），
  只是不再出现在常规流程入口上。

## 5. 启动即打开网页（`start.bat`）

```bat
set "APP_URL=http://127.0.0.1:8000/app/"
```

- 后端已在运行 → 打印提示后 `start "" "%APP_URL%"` 并退出；
- 后端未运行 → 先起一个隐藏的 PowerShell 子进程，`Start-Sleep 3` 等 uvicorn 监听起来，
  再 `Start-Process` 打开默认浏览器，然后前台正常跑 `python -m uvicorn ...`。

## 8. 已知限制

1. **只有三个真实视角**：270° 是侧面的镜像。如果以后拿到第四视角素材，放进
   `assets/phoebe3d/` 并在 `phoebe3d.js` 的 `FRAMES` 里改一行即可。
2. **不是真 3D 模型**：素材是逐帧照片，旋转是"相邻视角交叉淡化"，不是网格渲染；
   因此除 4 个角度外看起来是过渡而不是透视正确的中间姿态。
3. **换表情会整块换图**：6 种情绪是 6 套独立照片，切换时三个视角一起换（不是逐帧动画），
   所以表情只在"停留"时看得出变化；另外侧视图帽檐在抠图时有约 250px 的小缺口（源自素材本身
   帽檐与背景几乎同色、梯度又足够低）
4. **语音依赖系统中文音色**：Windows 需在"设置 → 时间和语言 → 语音"里装中文语音包，
   否则会用系统默认音色读中文（与 V2.1 的读题语音同一个限制）。
5. **答对时不播 TTS**：因为表情包浮层自带欢呼人声，两者同时响会互相盖住；
   想要"人声念鼓励语"可以调 `phoebe3dFeedback` 里 `correct` 分支的 `speak` 行为。
6. **自动跳题会跳过"难度感受"**：答对时不再询问感受，`feel` 记录为空，
   难度调整改由最近正确率窗口驱动（`adaptive/difficulty.py` 原有能力，未改算法）。
7. **能力推断对题量敏感**：不足 5 题只给"数据积累中"，不足 20 题置信度偏低，属刻意保守设计。
8. **AI 台词只在"点击"时触发**：答对 / 答错用本地即时文案，避免孩子每次答完都要等 1 秒网络；
   想改成答完也让 AI 说话，见 2.7 末尾。
9. **AI 台词有等待时间**：实测 DeepSeek 0.7~1.2 秒（首次可能 2~3 秒），期间字幕显示"让菲比看看你的学习情况…"；
   超过 14 秒或请求失败直接落到本地文案。
10. **左侧立牌在窄屏会缩小甚至隐藏**：≤900px 没有"左侧空白"，继续固定会挡住题目，所以隐藏
   （这正是"固定在左侧空白处"这个需求的物理前提）。
10. **点击会消耗 DeepSeek token**：每次点击一次调用（`max_tokens=120`），
    同一时刻只允许一个请求在飞（防狂点打风暴）；不想联网时设 `PHOEBE_AI_OFFLINE=1` 即退回纯本地。
