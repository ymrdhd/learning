# AI小学学习系统 V2.2 · 学生能力诊断系统

> 核心理念：**不看学生选了哪个年级，只看他答出来的表现。**
> 四年级的孩子来做数学诊断，如果只会 20 以内加减法，系统就老实告诉他"你的数学在一年级基础"。

---

## 一、24 个能力阶段模型

能力不再用"年级"表示，而是 `年级.等级` 的阶段串：

| 年级 | 阶段 | 等级名 |
| --- | --- | --- |
| 一年级 | 1.1 / 1.2 / 1.3 / 1.4 | 基础 / 熟练 / 进阶 / 挑战 |
| 二年级 | 2.1 / 2.2 / 2.3 / 2.4 | 同上 |
| … | … | … |
| 六年级 | 6.1 / 6.2 / 6.3 / 6.4 | 同上 |

- `3.2` = 三年级熟练阶段。
- 24 个阶段排成一条 `0~23` 的线性坐标（`backend/stages.py`），所有升级/回退都在坐标上做。
- 每个阶段配一个难度值（1.1 = 15，6.4 = 95，单调递增），供出题与知识点权重使用。
- 每科每个阶段都有对应的知识点（`stages.KNOWLEDGE`），例如数学 2.3 = 两步计算应用题、语文 4.2 = 病句修改、英语 5.2 = 形容词比较级。

## 二、诊断流程与算法

### 1. 流程

```
选择科目（数学/语文/英语）
      ↓
POST /api/diagnostic/start        → session_id（起点永远是 1.1）
      ↓
GET  /api/diagnostic/question     → 当前阶段随机 5 题（不下发答案）
POST /api/diagnostic/answer ×5    → 只回对错，不给正确答案
      ↓
一组题算一次正确率 → 决定下一组测哪个阶段（动态测试，不是固定 100 题）
      ↓
找到能力边界 → 生成能力画像 → 能力报告
```

### 2. 推进规则（每阶段 5 题一组）

| 正确率 | 判定 | 下一步 |
| --- | --- | --- |
| ≥ 90% | 掌握优秀（跳级） | 本年级内跳到「进阶」；已在进阶/挑战则进下一学年「基础」 |
| 85% ~ 90% | 掌握良好 | 进入下一学年基础 |
| 60% ~ 85% | 到了能力边界 | 记为**边界候选**，再往上探一级确认上沿 |
| < 60% | 这一级没达到 | 结束测试，能力落在边界候选（没有候选则落在最后一个通过的阶段） |

**能力区间**：`final_stage` 是最后一个确认达到的阶段，再上一级没通过，所以真实水平落在两级之间。
报告里显示成 `3.1～3.2 阶段`。

**收尾条件**：正确率跌破 60% / 连续两组都落在边界区间 / 达到 6.4 / 题量上限 60 题。

### 3. 举例

| 测试过程 | 正确率 | 结果 |
| --- | --- | --- |
| 1.1 → 1.3 → 2.1 → 2.3 | 100% / 100% / 100% / 100% | 跳到 3.1 |
| 3.1 | 70% | 记为边界候选，上探 3.2 |
| 3.2 | 50% | 结束，能力 = **3.1～3.2 阶段** |

## 三、能力评分算法 `calculate_ability()`

输入：答题记录（每条含阶段、难度、对错）、最终阶段。
输出：能力阶段、能力分数、置信度、能力区间、星级。

1. **加权正确率**：每题权重 = `1 + 难度/100`，难题答对更值钱，避免"刷简单题刷出高分"。
2. **能力分** = `0.5 × 阶段基准分 + 0.5 × 加权正确率 × 100`
   - 阶段基准分 = `35 + 阶段坐标 × 3.1`（1.1 → 35，6.4 → 约 100），夹到 0~100。
3. **置信度**：题量越多越可信，精确命中需求给的三点：

   | 题量 | 10 题 | 30 题 | 50 题 | > 50 题 |
   | --- | --- | --- | --- | --- |
   | 置信度 | 0.50 | 0.85 | 0.95 | 缓慢逼近 1.00 |

4. **星级**：能力分换算 1~5 星（每 20 分一星），`76 → ★★★★☆`。

## 四、知识点能力分析

不只给"数学 76 分"，而是拆到知识点（`student_knowledge_mastery` 表）：

```
数学能力：总分 76
  表内乘法          88   （5 题对 4 题）
  两步计算应用题     61   （5 题对 3 题）
  ...
优势：表内乘法        需要提升：两步计算应用题
```

- 掌握度 = 该知识点上的正确率（0~100）。**不用难度扣分**，否则"一年级全对"会被显示成 95 分，报告里凭空多出一个假短板；难度信息由能力阶段单独表达。
- 短板只认掌握度 < 70 的知识点；全都不错时报告写"暂时没有明显短板"。
- 诊断题和日常练习（`/submit`）都会累计掌握度，数据越用越准。

## 五、出题逻辑升级（不再是"只传年级"）

`deepseek.generate_question(..., ability=...)` 新增能力上下文，prompt 结构：

```
你是小学老师。

科目:数学
年级:三年级
知识点:两步计算应用题
难度:55/100
学生：四年级
当前能力：数学3.2阶段（三年级熟练）
目标：3.3阶段（三年级进阶）
知识点：两步计算应用题
当前掌握：62
请生成略高于当前能力的题目：让孩子努力一下能做对，不要超出目标阶段太多。
```

- 诊断题优先用**本地分阶段题库**（`diagnostic_bank.py`），保证题目严格落在被测阶段，离线可跑、结果可复现；题库没覆盖时自动回退到 DeepSeek（带上面的能力上下文），再不行才用内置兜底题。
- 日常练习（`GET /question`）一旦有了诊断画像，难度就围绕"下一个能力阶段"生成：
  `难度 = 0.5 × 能力分 + 0.5 × 目标阶段难度`；没有画像时沿用原来的自适应难度逻辑（不破坏旧行为）。

## 六、数据库结构变化

新增 4 张表，老库启动时由 `Base.metadata.create_all` 自动建表，**不需要手工迁移**：

### `diagnostic_sessions`（一场诊断）

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| student_id / subject | 哪个学生、哪一科 |
| start_time / end_time | 开始 / 结束时间 |
| current_stage | 当前正在测的阶段（如 3.2） |
| final_stage | 诊断出的最终能力阶段 |
| final_score | 最终能力分 |
| confidence | 置信度 |
| status | in_progress / finished |
| total_count / correct_count | 累计题量与答对数 |
| state | JSON：本阶段第几题、每个阶段正确率、边界候选等运行时状态 |

### `diagnostic_records`（每道诊断题）

| 字段 | 说明 |
| --- | --- |
| id / session_id / student_id / subject | 归属 |
| stage | 这道题属于哪个能力阶段 |
| knowledge_point | 知识点 |
| difficulty | 难度 |
| correct | 是否答对 |
| answer_time | 作答时间 |
| question_id / submitted | 对应题目与提交内容 |

### `ability_profile`（学生能力画像，一个学生+一科一行）

| 字段 | 说明 |
| --- | --- |
| id / student_id / subject | 归属（student_id + subject 唯一索引） |
| ability_stage | 能力阶段，如 `3.2` |
| ability_score | 能力分，如 `76` |
| confidence | 置信度，如 `0.82` |
| lower_stage / upper_stage | 能力区间（3.2 / 3.3） |
| questions / correct | 累计题量与答对数 |
| source | diagnostic / practice |
| updated_time | 更新时间 |

### `student_knowledge_mastery`（知识点掌握度）

| 字段 | 说明 |
| --- | --- |
| id / student_id / subject / knowledge_id | 归属（三列唯一索引） |
| stage | 该知识点主要命中的能力阶段 |
| mastery_score | 掌握度 0~100 |
| questions / correct | 题量与答对数 |
| difficulty_sum | 累计难度（用于显示平均难度） |
| updated_time | 更新时间 |

> 说明：诊断题**只写诊断表**，不写 `answer_records`、不改 `abilities`，因此不会污染原有的日常练习统计。

## 七、API 接口

### 主接口（需求指定的四个）

| 方法 | 路径 | 参数 | 返回 |
| --- | --- | --- | --- |
| POST | `/api/diagnostic/start` | `student_id`, `subject` | `session_id`, 起始阶段, 进度 |
| GET | `/api/diagnostic/question` | `session_id` | 题目、选项、当前阶段、进度（**不含答案/解析**） |
| POST | `/api/diagnostic/answer` | `session_id`, `question_id`, `answer` | `correct`、进度、是否结束（**不回正确答案**） |
| GET | `/api/diagnostic/report` | `student_id`, `subject`, 可选 `session_id` | 能力画像 + 知识点细分 + 优势/短板/建议 |

### 辅助接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/diagnostic/session?session_id=` | 某场诊断的进度与历史 |
| GET | `/api/diagnostic/profiles?student_id=` | 该学生各科能力画像 |
| GET | `/api/diagnostic/stages` | 24 个阶段字典（前端展示用） |

请求 / 返回示例：

```jsonc
// POST /api/diagnostic/start
{"student_id": 1, "subject": "数学"}
// → {"session_id": 2, "stage": "1.1", "stage_label": "一年级基础",
//    "progress": {"answered": 0, "total": 15, ...}}

// GET /api/diagnostic/question?session_id=2
// → {"question_id": 11, "question": "...", "options": {"A": "...", "B": "..."},
//    "stage": "1.1", "stage_label": "一年级基础", "knowledge": "20以内加减法",
//    "difficulty": 15, "progress": {...}}          // 没有 answer 字段

// POST /api/diagnostic/answer
{"session_id": 2, "question_id": 11, "answer": "B"}
// → {"correct": true, "stage": "1.3", "verdict": "excellent",
//    "message": "这一组掌握得很好，我们去试试更难的题！",
//    "progress": {"answered": 5, "total": 20, ...}, "finished": false}

// GET /api/diagnostic/report?student_id=1&subject=数学
// → {"available": true, "stage": "3.2", "range_label": "3.2～3.3",
//    "score": 76, "confidence": 0.82, "star_text": "★★★★☆",
//    "knowledge": [{"knowledge": "表内乘法", "mastery_score": 88, ...}],
//    "strengths": [...], "weaknesses": [...], "advice": [...], "history": [...]}
```

## 八、前端页面

| 页面 | 作用 |
| --- | --- |
| `diagnostic.html` | 能力诊断入口：选学生、选科目（数学/语文/英语）、看已有画像、开始诊断 |
| `diagnostic_test.html` | 诊断过程：显示"正在测试/当前阶段/进度 15/30"，只回对错，**不显示正确答案** |
| `diagnostic_report.html` | 能力报告：星级、当前阶段、能力区间、知识点条形图、优势、需要提升、学习建议、测试过程 |

练习页（`index.html`）加了「🧪 能力诊断」和「📊 我的能力报告」两个入口。
诊断过程页保留语音朗读（浏览器自带 Web Speech API），小朋友可以不看字先听懂题目。

## 九、自测

统一入口（推荐）：

```bash
python backend/verify_all.py                    # 全部 5 个套件
python backend/verify_all.py diagnostic diagweb # 只跑诊断相关
```

| 套件 | 内容 | 端口 |
| --- | --- | --- |
| `review` | 艾宾浩斯复习闭环 | 8899 |
| `flow` | 学习闭环回归 | 8900 |
| `diagnostic` | **能力诊断引擎**（阶段模型、评分算法、状态机、题库、API、双学生隔离） | 8902 |
| `web` | 前端语音与复习面板逻辑 | 无 |
| `diagweb` | **前端诊断页面逻辑**（页面元素一致性、进度、选项提交、报告渲染） | 无 |

也可以单独跑：

```bash
python backend/verify_diagnostic.py        # 端口可用 VERIFY_DIAG_PORT 改
node frontend/verify_diagnostic_web.js
```

`diagnostic` 套件会自拉临时后端 + 临时库，用两个学生跑完整场诊断：
学生 A 全程答对（能力自动升到 6.x）、学生 B 全程答错（停在 1.1），并验证两人数据完全隔离。

## 十、本地运行

```bash
# 1. 启动后端（双击 start.bat 同效）
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000

# 2. 浏览器打开
http://127.0.0.1:8000/app/                 # 日常练习
http://127.0.0.1:8000/app/diagnostic.html  # 能力诊断
```

老库（含现有学习数据）第一次启动会自动补出 4 张新表，原有数据不受影响。
