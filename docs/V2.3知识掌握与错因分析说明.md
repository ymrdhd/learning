# AI小学学习系统 V2.3 · 知识掌握模型 + 错因分析 + AI题目质量审核

> 版本说明：V2.2 已经能回答"学生大概是什么水平"（24 个能力阶段 + 能力画像）。
> V2.3 再往下钻一层，回答三个更具体的问题：
>
> 1. **具体哪些知识掌握了、哪些薄弱？**（知识掌握模型 MasteryEngine + 知识点体系）
> 2. **为什么错？**（错因分析：规则 + AI，写出原因和下一步建议）
> 3. **AI 出的题能不能用？**（题目质量审核 QuestionValidator，不合格的题不发给孩子）

全部本地运行、SQLite 存储、FastAPI 架构，数据一律绑定 `student_id`，不引入账号系统。

---

## 一、知识点体系（knowledge_points）

`stages.KNOWLEDGE`（每个能力阶段练哪个知识点）是唯一来源，V2.3 在它上面补出**学校式的层级结构**：

```
数学
├── 计算
│   ├── 表内乘法
│   │   ├── 2~5的乘法口诀
│   │   └── 6~9的乘法口诀
│   └── 两位数除法
├── 数与代数
├── 图形与几何
└── 应用题
    └── 两步计算应用题
```

| 字段 | 说明 |
| --- | --- |
| subject / grade / semester / chapter | 科目、年级、上册/下册、章节领域 |
| knowledge_name | 知识点名称（与其他模块对齐的唯一键） |
| parent_id | 父知识点 id，自关联成树（支持父/子知识点） |
| difficulty | 由所属能力阶段推导（3.2 → 55） |
| path | 完整路径：`数学 / 计算 / 表内乘法` |
| is_leaf | 是否叶子节点 |

- 三科共 **139 个节点**：3 个科目根 + 19 个章节领域 + 72 个知识点 + 45 个子知识点。
- 三科各 24 个知识点，与 24 个能力阶段**逐一对应**（`seed()` 时校验，缺一个直接报错）。
- 子知识点的年级/阶段继承父节点（`stage_of_any()`）。
- 启动时自动灌库（`knowledge_tree.ensure_seeded`），并把手里的掌握度数据挂到树上（`link_mastery`）。

## 二、掌握模型 MasteryEngine

`backend/mastery.py` —— 回答"这个学生在这个知识点上掌握到什么程度"。

输入：该知识点的历史答题记录（对错、难度、错误类型、时间）
输出：`mastery_score`（0~100）、`confidence`（0~1）、掌握等级、下次复习时间

算法四步：

| 步骤 | 规则 |
| --- | --- |
| 1. 加权正确率 | 难题答对更值钱：权重 = `1 + 难度/100` |
| 2. 题量收缩 | `score = 50 + (正确率×100 − 50) × n/(n+7.5)` |
| 3. 连续错误惩罚 | 最近连错 k 道扣 `4k` 分，最多扣 20 分（直接掉档） |
| 4. 复习加成 / 时间衰减 | 跨 ≥2 天练习最多 +6 分；超过 14 天没练，每多一周扣 1 分（最多扣 8 分） |

题量收缩让"做 5 道题"和"做 50 道题"的分数不一样（与需求给的两点对齐）：

| 情况 | 掌握度 | 置信度 | 等级 |
| --- | --- | --- | --- |
| 5 题全对 | **70** | **0.40** | 初步掌握 |
| 42/50 题正确 | 约 80 | 0.87 | 初步掌握 |
| 50 题全对 | 93 | 0.87 | 熟练 |
| 20 题全对 | 86 | 0.73 | 熟练 |
| 连续错 3 道（原本 93 分） | 74 | — | 初步掌握 |

- **等级分档**：≥85 熟练 / ≥70 初步掌握 / ≥50 巩固中 / >0 薄弱 / 0 未练习。
- **置信度** = `n/(n+7.5)`：5 题 0.40、20 题 0.73、50 题 0.87（上限 0.98）。
- **下次复习时间**：熟练 +7 天、初步掌握 +3 天、巩固中 +1 天、薄弱 +4 小时 —— 越熟间隔越长。
- 每次作答后按**该知识点的全部历史记录**重算（不是简单累加），所以连续错误降档、久不练习衰减都真实生效。

## 三、错因分析系统

### 1. 流程

```
学生答错 → 规则分析（本地、瞬时） → AI 深化（可选） → 错误原因 + 下一步建议
```

`POST /submit` 答错时立刻返回规则分析结果（不阻塞、不依赖网络）；
`POST /api/error/analyze` 会再走一遍 AI（配了 `DEEPSEEK_API_KEY` 时），拿到更细的原因描述。

### 2. 错误类型（按科目）

| 科目 | 错误类型 |
| --- | --- |
| 数学 | 概念错误 / 计算错误 / 审题错误 / 步骤错误 / 单位错误 |
| 语文 | 字词错误 / 阅读理解错误 / 信息定位错误 / 表达错误 |
| 英语 | 单词错误 / 拼写错误 / 语法错误 / 阅读错误 |

### 3. 规则判据（本地，全部可单测）

**数学**
- 把「−」算成了加法（应用题里"吃掉 3 个"答成 12+3）→ **概念错误**：`把「吃掉 / 减少」理解成了「增加」`
- 数字对但单位丢了 → **单位错误**
- 只差一点点（≤ max(1, 5%)）→ **计算错误**
- 题干长且含"一共/还剩/平均"等关键词，答案离得很远 → **审题错误**
- 多步计算（题干两个运算或难度 ≥55）→ **步骤错误**

**语文**：与正确项长度相同且有共同字 → 字词错误；带短文 → 阅读理解 / 信息定位错误；仿写造句类 → 表达错误。

**英语**：先看词形（go/goes/going）→ 语法错误；再看拼写距离 ≤2 → 拼写错误；带短文 → 阅读错误；否则单词错误。

### 4. 输出示例

```jsonc
// POST /api/error/analyze
{"student_id":1,"question_id":25,"answer":"15"}
// → {
//   "error_type": "概念错误",
//   "analysis": "把「吃掉 / 减少」理解成了「增加」：12 和 3 应该相减，结果是 9。",
//   "suggestion": "重新练习：两步计算应用题 的含义。先用自己的话说一遍，再做 3 道同类题。",
//   "source": "rule", "error_types": ["概念错误","计算错误","审题错误","步骤错误","单位错误"]
// }
```

## 四、错题本 wrong_questions

状态机（和孩子的学习节奏对齐）：

```
第一次答错 → NEW（未掌握）+ 生成错因分析
     ↓ 看讲解、练一道同知识点的相似题
答对 1 次  → LEARNING（巩固中）
     ↓ 再答对 1 次
答对 2 次  → MASTERED（已攻克）
     ↓ 万一又错了
又答错     → 回到 LEARNING
```

- "答对"是**按知识点**推进的：练相似题（同一知识点的另一道题）同样算数，孩子不必重做原题。
- 每道错题记录：错误次数、连对次数、最近错因、最近错误时间、下次复习时间。
- 统计三档：未掌握 / 巩固中 / 已攻克。

## 五、AI 题目质量审核 QuestionValidator

所有生成的题目（本地题库 + DeepSeek）**保存前必须过审**：

```
DeepSeek / 题库生成 → 格式检查 → 答案验证 → 难度验证 → 知识点验证 → 通过 → 保存
                                     ↓ 不合格
                              重试一次 → 仍不合格 → 内置兜底题（绝不把错题发给孩子）
```

| 检查 | 级别 | 说明 |
| --- | --- | --- |
| 题干/答案非空 | error | 空题直接拦 |
| 选项数量与重复 | error | 必须 4 个互不相同（数值等价也算重复：1.0 = 1.00） |
| 答案在选项中 | error | 答案字母必须存在 |
| **算式自检** | error | 题干只有一个两数运算时，本地算一遍比对答案（"除不尽保留两位小数"允许 0.011 误差） |
| 除以 0 | error | 直接拦 |
| 歧义选项 | error | "以上都对/都不对/不确定" |
| 答案泄漏 | warn | 题干出现答案原文 |
| 数字规模 / 超纲 | warn | 低阶段出现超 100 的数、过早出现分数/方程/比例等 |
| 知识点对不上 | warn | 题干与知识点关键词无关联（题库题由映射保证，跳过） |

审核结果随出题一起返回（`audit`），可直接在页面上看这道题是否达标。

## 六、Prompt 升级（出题带掌握度与错误历史）

```
你是小学老师。

科目:数学
年级:三年级
知识点:两步计算应用题
难度:55/100
学生：四年级
当前能力：数学3.2阶段（三年级熟练）
目标阶段：3.3（三年级进阶）
知识点：两步计算应用题
掌握度：62
错误历史：审题错误较多，出题时针对这个薄弱点设计
目标：生成一道略高于当前能力（3.3 阶段）的训练题，重点针对「审题错误」
出题要求：让孩子努力一下能做对，不要超出目标阶段太多。
```

## 七、数据库变化

### 新增 3 张表

**`knowledge_points`**（知识点体系）
`id / subject / grade / semester / chapter / knowledge_name / parent_id / difficulty / path / is_leaf / created_time`
索引：`(subject, knowledge_name)` 唯一、`parent_id`。

**`answer_error_analysis`**（错因分析）
`id / answer_record_id / student_id / subject / knowledge_id / question_id / error_type / analysis / suggestion / source / created_time`
索引：`(student_id, subject)`、`question_id`。

**`wrong_questions`**（错题本）
`id / student_id / subject / knowledge_id / question_id / stage / status / wrong_count / correct_streak / last_error_type / first_wrong_time / last_wrong_time / next_review_time / created_time / updated_time`
索引：`(student_id, status)`、`(student_id, question_id)` 唯一。

### 扩展 1 张表（数据库迁移，不重建、不丢数据）

`student_knowledge_mastery` 新增：

| 新字段 | 说明 |
| --- | --- |
| knowledge_point_id | 挂到知识点树（回填时按名称匹配） |
| grade | 知识点所在年级 |
| confidence | 掌握度置信度 |
| total_questions / correct_questions / wrong_questions | 题量 / 答对 / 答错 |
| consecutive_wrong | 最近连续错几道 |
| last_practice_time / next_review_time | 最近练习 / 下次复习时间 |

迁移方式（`database.migrate_data()`，启动时幂等执行）：
1. `ensure_schema` 给老表 `ALTER TABLE ADD COLUMN` 补齐新列；
2. SQL 把 V2.2 的 `questions → total_questions`、`correct → correct_questions` 搬过去，算出 `wrong_questions`，按题量补算 `confidence`，用 `updated_time` 填 `last_practice_time`；
3. **旧列原样保留**，随时可以回退；
4. `knowledge_tree.link_mastery()` 把已有掌握度挂到知识点树上；
5. `error_analysis.backfill()` 给历史错题补错因分析（最多 200 条，纯本地规则）。

真实库副本上的迁移验证结果：新表齐全、新字段齐全、知识点 139 个、V2.2 数据回填正确（12/10/2 + 置信度 0.62 + 年级 2）、历史错题补出 7 条错因、**旧表行数一行未变**。

## 八、API 文档

### 需求指定的 4 个接口

| 方法 | 路径 | 参数 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/mastery/{student_id}` | `subject`（默认数学） | 领域星级、每个知识点掌握度/置信度/题量/下次复习、三科汇总 |
| GET | `/api/errors/{student_id}` | `subject`、`limit` | 错因按类型/科目汇总 + 明细（题干、原因、建议） |
| POST | `/api/error/analyze` | `{student_id, question_id, answer}` 或 `{answer_record_id}`、`use_ai` | 错误类型、原因、建议、候选类型 |
| GET | `/api/report/knowledge` | `student_id`、`subject` | 平均掌握度、星级、领域汇总、已掌握/需提升、错因汇总、**今天的学习建议** |

### 补充接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/wrong_questions/{student_id}` | 错题本（`status=NEW/LEARNING/MASTERED` 可筛选 + 三档统计） |
| GET | `/api/knowledge/tree` | 知识点树（科目 → 章节 → 知识点 → 子知识点） |
| POST | `/api/knowledge/sync` | 重新同步知识点树并挂载掌握度 |

### 既有接口的变化（向后兼容）

- `GET /question`：难度改为围绕"下一个能力阶段"，prompt 带上掌握度与错误历史，返回新增 `audit`（质量审核结果）。
- `POST /submit`：答错时返回 `error_analysis`（错因），并新增 `mastery`（该知识点即时掌握度）与 `wrong_book`（三档统计）；原有字段一个没少。
- `GET /api/diagnostic/*`：诊断题也走质量审核，答错同样记错因、更新掌握度。
